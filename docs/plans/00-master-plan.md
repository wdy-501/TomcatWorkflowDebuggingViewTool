## 0. 一页结论

### 0.1 产品一句话

**TraceBoard 是一个“从一次点击开始、只根据本次真实运行生成调用电路板”的可视化调试工作台：它把前端控件、JS 方法、HTTP 请求、后端 Controller/实现类、SQL 影响行数、响应回调和 UI 变化连成一张图，并明确标出哪些数据没有采集到。**

它解决的不是“如何设断点”，而是：

> “我知道自己刚点了什么，但不知道数据在哪一层变成了我不想要的结果，也不知道下一步该翻哪个文件、哪个方法。”

### 0.2 三个必须守住的产品承诺

1. **首次失败即可出图**：不需要先跑成功案例，不需要预先扫描整个项目并画静态调用图。探针在启动时接入，第一次出错的那次操作就产生图；没走到的代码不出现。
2. **回放绝不再执行程序**：回放只读取已记录的事件流，不重新发请求、不重复提交订单、不写入数据库。工作台里没有“重跑这次操作”的按钮。
3. **不知道就说不知道**：正常返回 false、抛异常、后续未采集，是三种不同状态。第三方内部、被裁剪的变量、被脱敏的字段、丢失的关联都会在界面上有明确原因，不用一张“看起来完整”的图掩盖缺口。

### 0.3 产品边界（先讲清楚，避免后面返工）

- 不是断点调试器：不提供断点、单步、暂停程序、改变程序执行流的控制。
- 不是静态分析器：不预先构建全项目调用图；主图只来自本次执行。
- 不是生产 APM：默认用于本地/测试环境；不承诺低到可以常开在生产流量上的开销。
- 不是“自动告诉你 bug 在哪”的 AI 裁判：先给事实和第一个分歧点，业务对错由开发者判断；可以给“事实提示”，不能把提示伪装成结论。
- V1 以**单后端 JVM、单次用户操作**为主。多微服务、网关全链路、WebFlux 响应式、GraalVM native、Kotlin 协程、JSP 深层 JS 调试，不在 V1 的完整支持范围内，后文有明确条件。

### 0.4 先做哪条链路

按“最值得先验证的风险”排序，而不是按界面好看程度排序：

1. **P0 事实闭环**：一个 Spring Boot 2.7 + Vue3 示例项目，首次运行就能记录点击 → 请求 → Controller → Service → Mapper → SQL 影响行数 → 前端回调/提示；能回放；后台轮询不误并入。
2. **P1 本地 MVP**：本地启动器、IDEA/JAR 接入、工作台、请求切换、节点详情、状态语义、脱敏、离线。
3. **P2 全栈本地覆盖**：React/Webpack、Tomcat WAR/SSM、行级变量与实体字段变化、异步回调、四种本地接入方式。
4. **P3 云端模式**：首发只接收 Boot JAR；上传、沙箱、隔离数据库、启动诊断、预览注入、保留/清理。
5. **P4 深度与硬化**：云端 WAR、更细的 UI 效果、兼容矩阵、安装包、性能、用户测试、安全审查。

如果只做比赛演示：**P0 + P1 的本地垂直切片就足够讲清产品价值**；云端可以作为后续演示，不应为了“看起来完整”提前做一个没有隔离保障的上传环境。

**本计划里的 V1：** 首发范围 = P0–P3（云端只做 Boot JAR），并满足 P4 中与首发相关的硬化门槛；云端 WAR、更多 Tomcat/React 版本属于 V1.x 增强，不作为首发门槛。对外发布前，支持矩阵中承诺的单元必须有 CI/示例证据。P0+P1 是比赛/内部最小演示，不等于完整 V1。排期不足时，宁可把未完成的环境标成“仅本地/暂不支持”，不要把半成品写成“已支持”。

## 1. 产品定位与用户

### 1.1 目标用户

- 刚入行的 Java/前端开发者：会改业务功能，但不熟悉断点、调用栈、Tomcat 配置和跨层数据流。
- 正在维护别人代码的开发者：知道页面现象，不知道对应哪个 Controller/Service/Mapper。
- 需要处理真实业务数据、不愿把代码/参数/SQL 交给第三方平台的团队：使用本地模式。
- 参加课程/竞赛、需要快速定位“页面成功但数据没变”的学生团队：使用本地 + 云端演示。

### 1.2 三个典型场景

1. 点按钮后页面弹出看不懂的错误码，不知道是哪个方法返回的。
2. 表单提示保存成功，刷新后数据没变；数据库实际更新 0 行。
3. 没有异常、程序也跑完了，但最终业务结果不对；需要找出哪个方法里的变量/实体字段从 100 变成了 0。

共同点：用户知道“我点了什么”，不知道“该去看哪一层、哪个文件、哪个方法”。

### 1.3 为什么现有工具不够

| 工具 | 能看到 | 缺口 |
|---|---|---|
| 浏览器 DevTools | 控件、请求、JS 栈、DOM | 看不到 JVM 内的 Service/Mapper/实体字段和 SQL 影响行数 |
| IDEA 断点调试 | 任意方法内部变量 | 要先知道在哪打断点；会暂停程序；跨多个异步请求/前后端回调需要人工拼接 |
| APM（SkyWalking/Zipkin 等） | 服务级调用链、耗时 | 面向运维，通常不记录方法内变量；不把前端控件当起点；采样后缺口不面向开发者解释 |
| 日志 | 开发者自己打印的内容 | 需要事先埋点；不知道没打印的那一层发生了什么 |

TraceBoard 的差异：**以一次用户操作为中心，把前后端运行时事实放在同一张图上，并对缺口作明确标注。**

### 1.4 产品成功标准（可验收）

- 新手在示例项目中，从点击“保存”到指出“该查哪个方法” ≤ 5 分钟。
- 本地 IDEA 接入 ≤ 10 分钟；只有 JAR 的接入 ≤ 5 分钟（不含安装 JDK）。
- 对示例中的“0 行更新”，3 次点击内能读到：SQL 影响行数、Mapper 返回 0、Service 返回 true、无异常。
- 纯前端校验拦截时，能明确区分“确认没有发请求”和“前端采集未接入/请求可能丢失”。
- 回放期间，服务端写 SQL 次数 = 0，HTTP 写请求次数 = 0（自动断言）。
- 同一页面 20 次点击中，后台轮询被误并入操作图 = 0 次。
- 不静默丢弃事件：所有截断、采样、脱敏、未采集都有可见标记和原因。

## 2. 图的语义：一块电路板

### 2.1 映射表

| 电路板隐喻 | 产品实体 | 说明 |
|---|---|---|
| 电路板 | 一次用户操作会话 | 一次点击/提交触发的因果链，不是固定时间窗 |
| 开关 | 前端控件 | 按钮/链接/输入框；有 ID 显示 ID，无 ID 用可访问名称、文本、DOM 路径、位置综合标识 |
| 线路 | 调用关系 | 方法之间的调用边；异步延续用虚线/不同线型 |
| 元器件 | 方法 | 主图只放方法节点；控件和 HTTP 请求是特殊起点/切换节点 |
| 电流 | 本次执行的经过 | 实时高亮；回放时按时间轴点亮 |
| 读数 | 方法入参、返回、异常、耗时、变量变化、实体字段变化、SQL 行数、UI 效果 | 默认在详情抽屉里看，主图不堆满文本 |

### 2.2 主图的七条硬规则

1. **左侧保留前端图，右侧按请求分图。** 一个操作可能发多个请求（如“保存订单”后“刷新列表”）；点击左图里的请求入口，右侧切到该请求的后端图。两个请求再近也不能因为时间接近就合并。
2. **主图只放方法节点。** 控件是起点；HTTP 请求是前后端切换入口；文件名、行号、变量、UI 变化都在节点详情。
3. **同一方法执行 N 次只放一个节点，标 ×N。** 点开后可逐次查看第 1/2/3 次调用，尤其要能定位“哪一次的值坏了”。
4. **方法内部的变化要能看到过程。** 例如 `amount` 进入 100，中途在第 42 行变成 0，退出前又变回 100；详情要按行/字段列出 old→new。条件分支为什么走这边不专门解释，只给事实。
5. **默认突出项目方法。** 用户自己写的拦截器、转换器、校验器即使由 Vue/Axios/Spring 调用，也要出现；第三方库默认折叠，已记录的可以展开，没记录的明确写“本次未采集”。
6. **实时 + 回放。** 运行时实时高亮；结束后拖动时间轴回看。滑块停在哪，看到那一刻已发生的线路和数据。不提供断点/暂停/单步控制程序；可以暂停“看图”，不能暂停“程序”。
7. **状态必须区分。** 正常返回 false、抛异常、后续未采集是三种不同事实；业务结果是否正确由用户判断，工具先把事实摆清楚。

### 2.3 状态语义

| 状态 | 含义 | 界面表现 |
|---|---|---|
| `OK` | 方法正常返回（包括 true、数字、对象；返回 0 也是正常返回的事实） | 绿色/常规线；返回值在详情中展示 |
| `RETURNED_FALSE` | 方法正常返回了布尔 false | 琥珀色标签“正常返回 false”；不是异常 |
| `THREW` | 方法抛出异常 | 红色断线/闪电；“异常类型 + message + 顶部栈”可展开 |
| `NOT_COLLECTED_POLICY` | 被采集策略排除（如第三方包、未开启深度档） | 灰色虚线框；写明原因与如何开启 |
| `NOT_COLLECTED_LOST` | 事件丢失/关联丢失/采集中断 | 灰色虚线框；写明丢失环节与建议 |
| `NOT_COLLECTED_NO_DEBUG_INFO` | 字节码缺少调试信息，无法给局部变量名/行号 | 灰色虚线框；不猜变量名 |
| `TRUNCATED` | 值被截断/折叠/采样 | 条纹标记 + “已折叠 N 次/已截断至前 X 条” |
| `REDACTED` | 字段已脱敏 | 锁形标记；显示长度/哈希或占位符 |
| `UNKNOWN` | 进入方法但没有正常退出（进程结束、超时、崩溃） | 问号/断线；不伪装成成功 |
| `LOST`（关联） | 后端有请求但找不到前端根，或前端有请求但没有后端 span | 单独“游离片段”区；可手工关联并标 `MANUAL` |

**事实提示与结论的边界：** 工具可以提示“写 SQL 影响 0 行，但 HTTP 返回 200 且页面出现成功提示”，这是事实组合；不能直接说“这是一个 bug”，因为业务可能允许 0 行。提示用“事实摘要”样式，避免绿色成功/红色失败的简单裁判。

### 2.4 回放语义

- 回放输入是 append-only 事件流，不是重新执行程序。
- 状态 = 所有 `timestamp ≤ 滑块时间` 的事件；未来事件不显示或显示为未发生。
- 节点高亮、连线电流、变量值、SQL 行数、UI 效果都按同一虚拟时钟推进。
- 回放只读：不调用后端、不发出 HTTP、不触发 SQL；工作台不提供“再次执行”按钮。
- 回放的是**图和记录摘要**，不是像素级页面录屏。UI 效果显示为“检测到提示：保存成功”“表格行数 1→1”“按钮变为 disabled”等摘要；**用户已确认接受此语义，像素级 DOM 快照不进入 V1**。
- 可以暂停/播放回放视图、切换速度、跳转到事件；这些控制不控制程序本身。

## 3. 用户从进入网站到找出问题

### 3.1 第一次进入（0–3 分钟）

1. 官网首页提供一个**预置的坏示例**（“保存成功，但更新 0 行”），不需要上传就能点开看一张已完成的操作图。
2. 90 秒引导依次点亮：控件 → JS 处理 → 请求 → Controller → Service → Mapper → SQL 0 行 → 前端提示。
3. 引导明确指出图上的“本次未采集”是什么，以及怎样获得更多信息。
4. 用户选择：
   - 本地模式（推荐，隐私优先）；
   - 云端模式（首发上传 JAR + 前端包；WAR 用本地，云端 P4 开放）。

### 3.2 本地接入流程

1. 下载本地启动器（最终安装包内置精简 JRE；开发期可要求 JDK 21）。
2. 新建工作区，选择接入类型：
   - IDEA 启动的 Spring Boot；
   - IDEA 启动的 Tomcat；
   - 只有可执行 JAR；
   - 只有 WAR；
   - 前端单独用 Vite/Webpack 开发服务器。
3. 启动器生成一段 agent 参数/启动命令：
   - IDEA Spring Boot：把 `-javaagent:...` 复制到 Run/Debug Configurations 的 VM options；
   - IDEA Tomcat：把同样参数加到 Tomcat Server 的 VM options 或 `setenv.bat`；
   - JAR：启动器直接生成 `java -javaagent:... -jar app.jar` 命令并可代管进程；
   - WAR：启动器在独立 `CATALINA_BASE` 下部署，复用已有 Tomcat。
4. 启动应用；启动器检测 agent 握手、应用健康、端口、预览代理、前端 SDK 注入。
5. 打开工作台和预览地址，点击“开始记录”（或自动记录）。
6. 在预览页面里照常操作；左侧前端图实时点亮。
7. 点击请求入口，右侧查看后端；点节点看读数；拖时间轴回放。
8. 修复后重启应用，产生一个新的操作会话；V1 不做自动代码修复，只负责定位事实。

### 3.3 云端接入流程

1. 新建云端工作区，上传：
   - 可执行 JAR（如果前端已经打进 JAR，只需一个文件）；
   - 或 JAR + 独立前端 dist。
   - 首发云端不接收 WAR；WAR/SSM 请用本地模式，云端 WAR 在 P4 开放。
2. 选择 Java 版本（首发 JAR；平台先检测字节码版本并给出建议）。
3. 可选：上传 sourcemap、前端 trace build 产物、源码 zip（仅用于显示源码片段）、数据库 schema/seed SQL、环境变量/启动参数。
4. 平台创建隔离运行环境、启动应用、注入前端采集、打开预览。
5. 启动失败时显示分阶段诊断卡（详见第 10 节），可修改配置重试。
6. 与本地模式相同的工作台、相同的图、相同的回放。

### 3.4 一次调试闭环

1. 用户点击“保存订单”。
2. 图实时出现：`#btn-save` → `onSave` → `validateForm` → `buildPayload` → 请求。
3. 后端图出现：Controller → 接口 → 实现类 → Mapper → SQL。
4. 用户看到异常事实（如 0 行、返回 false、异常、未采集）。
5. 点节点读入参/返回/变量/实体字段/SQL/UI 效果。
6. 得出“应该检查哪个方法”的结论（事实链）。
7. 修改代码，重启/重新部署，重新操作，得到新会话；可对比两次事实（V1 先做并排查看，自动 diff 后置）。

### 3.5 新手保护

- 所有参数生成都可“一键复制”，不让用户手写复杂命令。
- 每个接入步骤都有“我卡住了”诊断：agent 未加载、端口占用、Java 版本不对、Tomcat 路径无效、前端注入被 CSP 拦截等。
- 不确定时明确说“未采集/无法确认”，不把空白图解释成“没有问题”。

### 4.2 区域与交互

- **顶部**：项目、操作标题、实时/回放、记录开关、会话选择、导出、采集范围。
- **左侧前端图**：控件 → JS 方法 → 请求入口；背景请求单独灰车道；请求入口是右侧切换器。
- **右侧后端图**：当前请求的方法调用图；请求标签页/下拉切换；异步子任务用虚线延展。
- **底部时间轴**：事件刻度（请求、SQL、异常、UI 变化、采集缺口），滑块，回放控制。
- **详情抽屉**：
  - 概览：签名、类/文件、行号、线程、耗时、状态、接口→实现关系、采集档位、标记。
  - 入参/返回：类型、值、截断/脱敏标记；对象按字段展开。
  - 变量变化：行号、变量/字段、old→new、第几次调用、循环折叠。
  - 调用次数：×N 的逐次列表；可跳转到该次调用的时间点。
  - SQL/数据影响：SQL 文本、参数（脱敏）、影响行数、读取行数、事务结果；不默认镜像整表。
  - UI 效果：提示文本、表格行数/首行摘要、按钮状态、路由变化。
  - 异常：类型、message、顶部栈、源码位置；完整栈按需展开。
  - 来源：源码片段（若可用）；“源码未提供”时给类/方法/行号；本地可打开 IDE。
  - 采集说明：哪些被排除、采样、截断、脱敏、丢弃，原因是什么。
- **搜索/过滤**：按方法名、类名、请求、状态筛选；只看项目方法/也看第三方；只看异常/未采集。
- **节点折叠**：第三方默认折叠为“第三方调用（N 个，未采集）”；已记录的可展开。被折叠不等于没发生。

### 4.3 视觉与可访问性

- 电路板风格：深色底板、青色线路、金色“电流”；异常红、false/0 琥珀、未采集灰虚线、第三方低饱和。
- 不靠颜色单独传达状态：同时使用图标、线型和文字（如“正常返回 false”“本次未采集”）。
- 键盘可导航；图支持缩放/平移/适配窗口；减少动画模式；对屏幕阅读器提供节点详情文本。
- 节点过多时：项目方法优先，第三方折叠；超过阈值按类/包折叠；提供搜索和“只看本次出错链路”。

### 4.4 空状态与错误状态

| 情况 | 界面必须说什么 |
|---|---|
| agent 未连接 | “后端采集未接入：没有收到 JVM 握手”；给检查清单，不显示空后端图伪装成功 |
| 前端 SDK 未连接 | “前端采集未接入：无法确认点击与请求”；给注入/CSP 诊断 |
| 只有前端图 | “本次操作未产生请求：已确认/无法确认”二选一，说明证据 |
| 只有后端图 | “未找到对应的前端操作根”；片段放游离区，可手工关联 |
| 应用启动失败 | 显示启动阶段、日志尾部、结构化原因、修复建议 |
| 录制被暂停/中断 | 时间轴出现“采集中断”缺口；前后事件不假装连续 |

## 5. 贯穿案例 A：页面提示成功，数据库更新 0 行

### 5.1 示例场景

- 示例项目：`BuggyShop`（Spring Boot 2.7 + MyBatis + MySQL/H2 + Vue3/Vite）。
- 数据：`orders` 表有 `id=1001, status=1, version=4`。
- 页面打开时把订单版本回显为 `version=3`（已被别人更新过一次，页面数据过期）。
- 用户把状态改为“已支付”，点击 `#btn-save`。
- 前端发出：
  - 请求 1：`POST /api/orders/1001/status`，body `{status:2, version:3}`；
  - 响应回调里触发请求 2：`GET /api/orders?page=1` 刷新列表。
- 后端 SQL：
  ```sql
  UPDATE orders
  SET status = #{status}, version = version + 1
  WHERE id = #{id} AND version = #{version}
  ```
- 由于数据库当前 `version=4`、请求带 `version=3`，SQL 影响 0 行。
- `OrderServiceImpl.updateStatus` 拿到 Mapper 返回的 `0`，但没有检查，直接 `return true`。
- Controller 返回 HTTP 200，前端 `.then` 弹出“保存成功”，随后刷新列表；列表仍是旧状态。
- 页面同时有每 30 秒一次的通知轮询 `GET /api/notifications`。

### 5.2 用户第一眼看到什么

**顶部操作摘要（事实，不是结论）：**

> 点击 `#btn-save 保存订单` · 本次操作 2 个请求（1 写 1 读） · 1 条写 SQL 影响 **0 行** · 0 个异常 · 检测到成功提示“保存成功” · 另有 2 个背景轮询未归属本次操作

**左图：**

`#btn-save` → `OrderEdit.onSave` → `validateForm`（✓）→ `buildPayload` → `Axios 请求拦截器` → `POST /api/orders/1001/status` → `then(onSaved)` → `toast('保存成功')` + `GET /api/orders`（请求 2）。

**右图（默认选中请求 1）：**

`OrderController.updateStatus` → `OrderService`（接口）→ `OrderServiceImpl.updateStatus` → `OrderMapper.updateStatus`（琥珀色“返回 0”）→ `SQL UPDATE ... rows=0`。

没有红色异常；Service 节点显示返回 `true`；请求 1 的响应是 200。

**底部时间轴：**

点击 0ms → 请求 1 120ms → SQL 155ms → 响应 160ms → toast 175ms → 请求 2 190ms。

**右侧详情抽屉初始关闭**；图上只有节点名、状态标记和关键事实徽标，不把变量铺满主图。

### 5.3 用户接下来点什么、读到什么

**第 1 次点击：Mapper/SQL 节点（琥珀色“返回 0”）。**

详情读到：

- SQL：`UPDATE orders SET status=?, version=version+1 WHERE id=? AND version=?`
- 参数：`id=1001, status=2, version=3`
- `rowsAffected=0`
- 事务：已提交（不是回滚）
- 耗时、线程、Mapper 方法（`OrderMapper.updateStatus`）与 `OrderMapper.xml` 的源码位置（若提供源码）
- 这次调用是第 1 次/共 1 次

**第 2 次点击：`OrderServiceImpl.updateStatus` 节点。**

详情读到：

- 入参：`orderId=1001, status=2, version=3`
- 调用 `orderMapper.updateStatus(...)` 的返回值：`0`
- 局部变量 `affected=0`（L2 深度采集时；没有 L2 时明确标“局部变量本次未采集”，但 Mapper 的返回 0 和 Service 的返回 true 仍在图上）
- 返回：`true`（第 47 行）
- 没有异常
- 调用次数：1/1

**第 3 次点击：前端 toast / UI 效果节点。**

详情读到：

- 响应 200 到达页面
- 回调 `onSaved`（有构建插件时）调用 `toast.success('保存成功')`
- 检测到短暂提示文本“保存成功”
- 随后刷新列表的请求 2 是本次操作因果链的一部分

### 5.4 凭什么判断该回去检查哪个方法

事实链：

1. `OrderMapper.updateStatus` 实际返回 `0`，SQL 影响 0 行；不是异常，也不是“没采集到”。
2. `OrderServiceImpl.updateStatus` 拿到了这个 `0`，没有抛出异常，仍然返回 `true`。
3. Controller 把 `true` 映射成成功响应；前端按成功处理并提示。
4. 因此，**第一个把“0 行”吞掉、没有让它变成失败的地方是 `OrderServiceImpl.updateStatus`**；最该先看它的第 42–47 行（是否检查影响行数）。
5. 同时，0 行的直接原因是 WHERE 条件没有匹配：请求带 `version=3`，数据库当前是 `version=4`。这要回到 `OrderMapper.xml` 的 WHERE 条件和页面版本字段回显/刷新逻辑去查。

结论卡可以写成：

> 先查 `OrderServiceImpl.updateStatus`：它在 Mapper 返回 0 后仍返回 true。  
> 再查 `OrderMapper.xml` 的版本条件及页面 version=3 的来源：数据库当前 version=4，条件不匹配。  
> 工具只确认事实，不替你判断业务上应该“提示失败”还是“自动刷新后重试”。

### 5.5 “100 变成 0”应该怎么分流

这是同一张图的另一种读法。不要一上来翻所有文件，按第一个分歧点分流：

| 第一个分歧点 | 该查哪里 |
|---|---|
| 输入框值是 100，但请求体里已经是 0 | 前端组装/格式化/校验/项目请求拦截器；看 `buildPayload` 和拦截器节点的 before→after |
| 请求体是 100，但 Controller 入参是 0 | 参数绑定、反序列化、过滤器/转换器；项目转换器会出现在图上，框架绑定可能标“未采集” |
| Controller 入参是 100，调 Service 前变成 0 | Controller 方法内部；看局部变量/参数传递 |
| Service 入参是 100，SQL 参数或实体字段是 0 | Service 内部修改；看字段写入的行号、old→new、第几次调用 |
| SQL 参数是 100，但数据库结果不对 | SQL 条件、数据库当前值、事务；工具给影响行数和参数，不默认镜像整表 |
| 响应里是 0，但页面显示 100 | 前端回调/转换/缓存；看回调、UI 效果和后续请求 |

这张表就是产品要帮用户建立的判断方式：**先找第一个和预期不一致的地方，再看它后面有没有被吞掉/改写。**

### 5.6 如果这一层没有采集到

- 如果是局部变量没开 L2：Service 节点显示“局部变量本次未采集（采集档位 L1）”，但 Mapper 返回 0 与 Service 返回 true 仍可见，0 行结论仍成立。
- 如果是 JAR 被 strip 掉调试信息：类/方法名仍在（未混淆时），行号和局部变量名显示“未采集（缺少调试信息）”，不猜。
- 如果是第三方框架内部（例如参数绑定）：显示框架边界节点“本次未采集”，不假装看到了内部每一步。
- 如果 Mapper 节点根本没有：说明探针未覆盖 MyBatis/JDBC 或关联丢失，显示采集缺口和原因，不能把“没记录”当成“没执行”。

### 5.7 回放与第二条请求

- 拖到 SQL 时刻：Service 尚未返回，toast 还没出现；看到 SQL 参数和 0 行。
- 拖到末尾：toast 出现，请求 2 已发出；看到“成功提示”是在 0 行之后发生的。
- 点请求 2：右侧切到列表查询图；列表响应仍是旧状态；表格刷新摘要“行数 1→1，状态仍为待支付”。这说明“刷新了但数据没变”。
- 背景轮询在灰色车道，标注“定时器发起，未归属本次点击”；点它可单独查看，但不会混入本次操作的后端图。
- 回放期间不重新发 POST/GET，不写数据库；界面明确显示“只读回放”。

### 5.8 案例 A 验收标准

- 首次运行（此前没有任何成功请求）即可出图。
- 3 次点击内读到 SQL 0 行、Mapper 返回 0、Service 返回 true、无异常。
- 能指出 `OrderServiceImpl.updateStatus` 和 `OrderMapper.xml` 两处需要检查，并给出事实依据。
- 请求 1、请求 2、后台轮询三者归属正确，切换正确。
- 回放前后，服务端写 SQL 计数为 0。
- 如果关闭 L2 局部变量，图仍能支撑“0 行被吞”的结论，缺口有明确标记。

### 5.9 同一张图怎么看“页面弹出错误码”

- 先点错误提示/响应节点：详情里有 HTTP 状态、响应 body 的 code/message、前端提示文本。
- 若 code 来自后端：点 Controller/Service 节点，看返回值或异常；红色是异常，琥珀是正常返回了失败码/false；详情给出源码位置。
- 若 code 是前端映射：看回调/转换节点（有构建插件时）或 UI 效果；没有插件时明确“前端内部未采集”，但仍能定位到哪个请求的响应。
- 若错误提示根本没有后端请求：右图空状态会区分“已确认未发请求”“发了但失败”“前端采集未接入”，不会把空白当答案。

## 6. 贯穿案例 B：纯前端校验，请求根本没发

### 6.1 场景

用户把金额清空（或输入 `0`），点击“保存”。`validateForm()` 返回 `false`，页面在金额输入框下显示“金额必须大于 0”，没有发出任何网络请求。

### 6.2 第一眼看到什么

- 左侧前端图：
  `#btn-save` → `OrderEdit.onSave` → `validateForm`（琥珀色“正常返回 false”）→ `setFormError('金额必须大于 0')` → 终止节点“未发起 HTTP 请求”。
- 右侧后端区域不是空白，而是空状态：
  > 本次操作未产生后端请求。  
  > 证据：前端 SDK 在线；从点击到 1.5 秒观察窗内，fetch/XHR 请求数 = 0；不是采集丢失。
- 底部时间轴只有前端事件，没有请求刻度。
- 如果请求确实尝试过但被浏览器/CORS/断网拦截，会显示一个失败的请求节点；不会和“没发请求”混为一谈。

### 6.3 点开 validateForm 节点读到什么

- 文件/函数/行号（构建插件或 sourcemap 可用时）。
- 入参/读取的表单字段：`amount = "0"` 或空字符串。
- 校验结果：`false`。
- 错误文本：“金额必须大于 0”。
- 局部变量（L2/构建插件）：`parsedAmount=0`、`valid=false`，以及产生 false 的那一行。
- 如果没有源码映射/构建插件：至少能看到控件身份、`validateForm` 包装器返回 false、错误提示 DOM 变化；详情明确写“JS 内部变量本次未采集”，并给出开启方式。

### 6.4 “确认没发请求”和“没采集到”必须分开

| 状态 | 证据 | 界面文案 |
|---|---|---|
| 确认没发 | SDK 在线、采集正常、观察窗内请求计数 0、handler 正常结束 | “已确认：本次点击因果链内没有网络请求” |
| 可能没发但无法确认 | SDK 未接入/被 CSP 拦截/录制已暂停 | “无法确认是否发请求：前端采集未接入/采集中断” |
| 发了但失败 | 有请求节点，状态为 CORS/网络错误/4xx/5xx | 展示请求失败状态和错误 |
| 发了但后端没记录 | 前端有请求，后端无对应 span | 标 `LOST` 或时间窗指纹推断，进入游离区，不假装成功 |

### 6.5 降级情况

- 只有压缩后的前端包、没有 sourcemap：能看到控件、点击、`validateForm` 包装结果、DOM 错误提示、请求数为 0；看不到原始函数名/行号/局部变量。
- 无法重新打包：运行时 SDK 仍然能证明“没有请求”；但内部变量需要 sourcemap/构建插件，详情必须说明。
- 有构建插件：可看到校验函数、行号、`amount` 的变化和错误文本来源，直接指向前端校验代码。

### 6.6 案例 B 验收标准

- 不发起后端图的情况下，用户仍能判断“问题在前端校验，不在后端”。
- “没发请求”有证据，不把空白当结论。
- 如果只有压缩包，明确列出能看到/看不到什么，并给出提升方式。

## 7. 数据从哪里来：用户要做什么、工具接触什么、换来什么

### 7.1 一句话原理

浏览器页面看不见 JVM 里的变量；所以后端需要一个进入 JVM 的**Java agent**（启动参数加载，不需要改业务代码）；前端需要一个页面里的 **runtime SDK**；如果还要看 JS 方法内部变量，需要在构建时加一个**构建插件**，把探针插进前端代码。

### 7.2 三件事必须分开说（回答“为什么不预扫描也能画图”）

| 事情 | 做什么 | 是否必需 | 产出 |
|---|---|---|---|
| 读源码 | 仅在展示时按需读取文件片段/行号；本地从项目目录读，云端只在用户上传源码 zip 时读 | 否。没有源码仍可画运行时图 | 详情里的源码片段；不是图拓扑的来源 |
| 处理字节码 | agent 在类加载时改写目标类，在方法进出/字段写入等位置插入很小的探针；不是反编译，不扫描全项目 | 是（后端深层事实） | 方法调用事件、SQL/行数、变量/字段事件 |
| 接触运行时业务值 | 探针在运行到该行时读取参数、返回、选中的局部变量/字段；有预算、脱敏、截断 | 是（读数） | 入参、返回、异常、字段 old→new、对象身份等 |

因此：

- **不预扫描全项目**：不构建静态调用图；图只由本次执行事件拼出来。
- **首次失败就能画**：agent 在应用启动时已就位；第一次点击就记录。
- **源码不是图的来源**：源码只影响“能不能展示片段/原始名字”，不影响“走过了哪些方法”。
- **字节码不是全量分析**：只处理配置范围内、实际加载的类；没加载/没执行的不出现。

### 7.3 前端接入分级

| 级别 | 用户做什么 | 工具接触什么 | 能看到 | 看不到/条件 |
|---|---|---|---|---|
| F0 仅有压缩包 | 云端上传 dist，或本地代理注入 runtime SDK；不需要改前端 | 点击/提交事件、控件身份、fetch/XHR、DOM 变化、控制台错误 | 控件、请求与响应体、toast/表格/按钮变化、请求数证据；压缩后的文件名/位置 | 原始函数名/行号（除非有 sourcemap）、JS 局部变量、回调内部逻辑 |
| F1 压缩包 + sourcemap | 上传/保留 sourcemap | 在 F0 基础上映射 sourcemap | 原始文件、函数名、行号 | 局部变量值仍不可得 |
| F2 构建插件（推荐） | Vite/Webpack 加插件，重新构建；上传 trace build | AST 插桩：函数入口/关键赋值/事件处理器/异步回调；产出 manifest | 方法名、文件行号、局部变量变化、控件→处理器、回调→toast/刷新 | 第三方库内部仍需折叠/未采集；构建时间增加 |
| F3 浏览器扩展/CDP（后续可选） | 本地装扩展 | 浏览器调试协议 | 无需重打包的有限追踪 | 仅本地、稳定性差、云端不适用；不作为 V1 主路径 |

**决策：** F0/F1 是“必须先能用”的降级路径；F2 是前端深层的推荐路径；F3 放到后续，不进入 V1 承诺。

### 7.4 后端接入与探针

**接入方式：**

1. **启动时 `-javaagent`（主路径）**：从第一个请求开始采集，不需要先跑成功案例。IDEA/JAR/WAR 都是把参数加到 JVM，不改业务代码。
2. **动态 attach（辅助）**：对已经在运行的项目附加，方便但会漏掉之前的操作；JDK 21 起有动态加载警告/限制，不作为主路径。
3. **Tomcat**：agent 必须加到 Tomcat 的 JVM，而不是 webapp 的 classpath；IDEA Tomcat run config 或 `setenv.bat`/`CATALINA_OPTS`。

**探针挂点：**

- Servlet/Spring MVC 请求入口：建立 `traceId`、请求图、Controller 选择。
- 项目方法：包范围根据启动包/`BOOT-INF/classes`/`WEB-INF/classes` 等 CodeSource 推断，不扫描源码；进入/退出、耗时、参数、返回、异常。
- 接口与实现：按运行时实际类显示；例如 `OrderService` 接口 → `OrderServiceImpl.updateStatus`，接口作为标签/端口，不制造重复噪音。
- MyBatis Executor / JDBC：SQL 文本、参数（脱敏）、`executeUpdate` 影响行数、查询行数（有上限）、事务提交/回滚。
- 实体字段写入：项目类 `PUTFIELD/PUTSTATIC` 的 old→new、对象身份、创建/修改；JPA 懒加载代理不触发 getter，未加载就标 `LazyProxy`。
- 异步：常见线程池/CompletableFuture/@Async 的上下文传播；丢失就标 `LOST`，不硬连。
- 失败策略：探针异常不能阻止应用启动；记录“采集器内部错误”，应用继续跑，图显示缺口。

**明确降级/不支持：**

- 局部变量需要 `LocalVariableTable`。直接 `javac` 默认通常只有源文件/行号，不一定有局部变量表；主流 Maven/Gradle 构建默认通常带 `-g`。若被 `-g:none`/strip/混淆，局部变量与行号缺失，显示 `NOT_COLLECTED_NO_DEBUG_INFO`，不猜。
- 字节码加密、GraalVM native、JNI/本地方法、跨 webapp 调用、MQ/定时任务作为点击根、Kotlin 协程上下文、JDK 21 虚拟线程的完整跨线程上下文：V1 不支持或仅基础支持。
- JPA/Hibernate：V1 承诺“实体字段写入 + JDBC SQL/行数”，不承诺 flush 级完整因果；flush 时序可标“未采集”。

### 7.5 只给压缩后的前端包和 JAR，究竟能看到什么（回答 Q1）

**只看得到：**

- 前端：点击的控件（ID/名称/文本/DOM 路径/位置）、事件类型、请求 URL/method/请求体/响应体（同源代理下）、toast/表格/按钮等 DOM 变化、控制台错误、时间。压缩后的栈位置可能显示为 `app.xxxx.js:1:23456`，函数名可能被压缩。
- 后端（JAR 未混淆且带调试信息）：类/方法名、行号、参数值、返回值、异常、耗时、Controller/接口/实现、SQL 与影响行数、线程、事务结果。
- 关联：同源代理/允许 trace header 时能精确关联；否则可能只有 `LOST` 或 `INFERRED` 片段。

**想进一步看到：**

| 想看到 | 需要额外提供/配置 |
|---|---|
| 前端原始方法名、文件行号 | 构建时保留 sourcemap 并上传/可访问；或在 F2 trace build 中产出 manifest |
| 前端 JS 局部变量每次赋值 | 加 Vite/Webpack 构建插件重新打包（F2）；sourcemap 本身不提供变量值 |
| 后端源码片段 | 可选上传源码 zip（云端）或配置本地项目根目录；图/变量不依赖源码，只影响展示 |
| 后端局部变量名/行级变化 | 构建时保留调试信息（Maven/Gradle 默认通常有；不要 strip/混淆）；开启 L2 深度采集并选中方法 |
| 实体字段 before/after | 默认 L1 对项目实体字段做差异；若字段在第三方/懒加载代理里，标未采集/LazyProxy |
| 完整第三方内部调用 | 默认折叠；可配置扩展包，但会增加开销和风险，不承诺完整 |

**不需要做的：** 不需要先在代码里打断点、加日志、跑成功案例；不需要预先画出全项目调用图；不需要改业务代码才能拿到 L0/L1 事实。

### 7.6 用户要做什么/工具接触什么/代价对照

| 接入 | 用户动作 | 工具接触 | 换来 | 代价/限制 |
|---|---|---|---|---|
| Java 启动 agent | 复制一段 VM 参数/启动命令 | 目标 JVM 的字节码、方法参数/返回、选中变量/字段、SQL、线程 | 后端运行时方法图与读数 | 需要启动时加参数；动态 attach 会漏早期事件 |
| 本地启动器 | 装本地版，按向导启动 | 本机进程、日志、端口、预览代理 | 一站式本地工作台、离线 | 工作台本身需要 Java 21（最终安装包内置 JRE） |
| 前端 runtime SDK | 通常由代理自动注入，或加一行 script | 预览页面的点击/网络/DOM | 控件、请求、UI 效果 | 看不到 JS 局部变量；CSP 可能阻止注入 |
| 前端构建插件 | 加插件重新构建 | 源码 AST、构建产物、sourcemap/manifest | JS 方法、行号、局部变量、回调 | 构建时间增加；只处理项目源码，不处理第三方内部 |
| sourcemap | 构建保留/上传 | 压缩代码到源码的映射 | 原始名字/行号 | 不含局部变量值；可能需要处理 sourcesContent 隐私 |
| 源码 zip/项目根 | 可选提供 | 源码文件读取 | 详情源码片段/打开 IDE | 不是图/变量的前提；云端源码需加密/保留策略 |
| 云端上传 | 首发传 JAR + dist（或单 JAR）；WAR 用本地/P4 | 隔离环境中的运行、文件、数据库 | 免本地环境，在线预览 | 只适合非敏感测试项目；外部 DB/内网服务不支持 |

### 7.7 Java 版本与兼容依据

依据必须是可复现产物，不是口头声明：

## 8. 一次点击、多个请求、后端执行、前端回调如何连起来

### 8.1 关联链

```text
点击控件（rootEvent / clickId）
  → 前端处理器 span
  → fetch/XHR（带 traceparent / clickId）
  → Java 请求入口（读取 traceparent）
  → Controller → Service → Mapper → SQL
  → HTTP 响应
  → 前端响应回调 span（若可采集）
  → toast / 表格刷新 / 按钮状态 / 后续请求
```

- 前端生成 W3C `traceparent`；后端 agent 读取并附着到请求线程。
- 点击根有 `clickId`；同步发起的请求、响应回调里发起的请求，通过因果上下文挂到同一个操作。
- 服务端内部异步行，通过线程池/CompletableFuture/@Async 传播上下文；丢失则单独标片段。

### 8.2 多个请求与后台轮询（硬规则）

- **请求 1（保存）** 和 **请求 2（刷新列表）**：请求 2 是响应回调里发起的，属于同一操作的因果链；左侧两个请求入口，右侧各自一张后端图，点击切换。
- **后台通知轮询**：由 `setInterval` 等定时器发起，没有本次点击的上下文；即使时间上重叠，也放入灰色“背景请求，未归属”车道。默认不并入；可以单独查看。
- **周期检测**：同一 endpoint 在点击前已周期性出现 ≥2 次，或调度栈含 timer origin，判为后台。
- **两个很近的点击**：各自是独立操作根；工作台分别建板，不因为时间近而合并。
- **点击回调里创建的定时器**：首次请求可属于本次；后续重复轮询归背景，并明确标注“由本次操作创建，但后续轮询未归属”。
- 不静默丢：所有未归属/游离请求都进入“游离区”，可手工关联；手工关联标 `MANUAL`。

### 8.3 置信度与未关联（回答 Q2）

| 置信度 | 条件 | 界面 |
|---|---|---|
| `EXACT` | traceparent + clickId 链路完整 | 实线，默认展示 |
| `INFERRED` | header 丢失，但时间窗 + method/path + bodyHash 等指纹吻合 | 点线/问号，明确“推断，可手工确认” |
| `LOST` | 只有一端（前端有请求后端无 span，或后端有请求无前端根） | 游离区；不强行并入 |
| `MANUAL` | 用户手工建立关联 | 虚线 + 手工标记；回放保持，但不伪装自动 |

未关联的呈现：

- 前端没有对应请求：左图请求节点灰/问号，右侧显示“后端未采集到该请求”，允许查看游离后端片段。
- 后端有请求但无前端根：右侧单独“游离后端请求”入口，显示可确定的事实；可手工关联。
- 网关/CORS 丢 header：优先同源代理；agent 允许 trace header 的 CORS preflight；仍丢失则 `INFERRED/LOST`，不静默合并。

### 8.4 异步、跨线程、跨服务

- 常见线程池/CompletableFuture/@Async：传播操作上下文，子任务作为异步子图。
- 上下文丢失：子任务显示为游离片段/`LOST`，不强行连到错误父节点。
- 前端异步回调：通过构建插件的调度点包装（Promise.then/catch、setTimeout、rAF 等）传播；没有插件时只能显示请求响应和 UI 效果，回调函数可能标“未采集”。
- 网关/多服务：V1 只保证单后端 JVM；traceparent 预留，跨服务图不在 V1 承诺。跨服务调用显示为“出站请求（后续服务未采集）”。

### 8.5 图聚合规则

- 节点 key：后端 `class#method(descriptor)`；前端 `source/function`（无源码时用稳定控件+包装器标识）。
- 同 key 合并为一个节点，`count` 显示执行次数；详情按 `invocationIndex` 分开。
- 状态取最严重优先级：`THREW > UNKNOWN > NOT_COLLECTED > TRUNCATED > RETURNED_FALSE > OK`；但每个 invocation 保留自己的真实状态。
- 边按 `(parentKey→childKey)` 合并并计数；保留代表 span 和时间。
- 递归/环：按深度折叠，标“递归/循环”；不无限展开。
- 第三方：默认折叠为边界节点“第三方调用 N 个（已记录/未采集）”；展开只显示已记录内容。
- 节点预算：默认一次会话最多展示项目方法节点 N 个（可配置），超出按包/类折叠，UI 明确“已折叠，不表示未执行”。

**×3 的具体读法示例：** `convertRow` 在刷新列表时执行 3 次，主图只画一个节点并标 ×3。点开“调用次数”：
- 第 1 次：`amount=100`；
- 第 2 次：`amount=0`（可从该次调用跳到时间轴对应时刻）；
- 第 3 次：`amount=100`。

用户不需要在主图里找三个同名节点，也能指出“坏在第 2 次”。如果采集被截断/采样，逐次列表会明确缺口，而不是只显示一个看似正常的聚合值。

### 8.6 为什么不需要预扫描（回答 Q3）

- **源码读取**：只在需要显示片段时进行；不是图拓扑的来源。
- **字节码处理**：agent 在类加载时插桩；只处理实际加载、配置范围内的类；不需要项目的静态调用图。读取 JAR/WAR 的包清单/启动类只是为了确定插桩范围，不是“预先扫描并画图”。
- **运行时值**：探针在实际执行到该行时读取；不在启动时扫描所有对象/变量。
- 图是事件流的派生：append 事件 → 增量 patch 图；没有执行的分支、没有加载的类、没走到的代码不出现。

## 9. 变量与数据采集的成本、预算与隐私（回答 Q4）

### 9.1 三档采集

| 档位 | 记录内容 | 适用 |
|---|---|---|
| L0（默认/基础） | 方法进出、耗时、状态、异常、标量参数/返回、HTTP、SQL 文本与影响行数、UI 事件 | 第一现场、低开销、0 行/异常/纯前端问题 |
| L1（推荐） | 在 L0 上增加对象摘要（深度/字段上限）、项目实体字段 diff、SQL 参数（脱敏）、集合大小、UI 效果摘要 | 大多数业务排查；100→0 的实体/参数层定位 |
| L2（深度，按需） | 选中方法的行级局部变量写入、字段 old→new、逐次调用、循环折叠 | 需要“哪一行/哪个变量”时；单请求/选中方法，开销更高 |

**默认策略：** 本地默认 L1，云端默认 L0/L1（可调）；L2 默认关闭，用户在节点上开启“深度采集”后重新运行同一次失败操作（不要求先跑成功案例）。运行前可设置只对焦点包/方法开 L2。

### 9.2 预算与降级

- 单 span ≤ 64KB；单请求 ≤ 4MB；对象深度 ≤ 4；单对象字段 ≤ 30；集合前 200 项；字符串前 2KB；SQL 文本/参数各自限制。
- 每个会话有事件/字节预算；超出后按优先级采样/丢弃，并**计数**。
- 循环内重复写入合并为“第 1..N 次”，保留首/尾/样本；展开可看样本，标“已折叠”。
- 高频方法按速率采样；图显示“本次采样/未全量记录”。
- 所有丢弃/截断/采样必须出现在 UI 的采集说明里；**静默丢弃是产品不可接受的失败。**

### 9.3 大对象、循环、敏感字段

- 大对象：身份 + 类型 + 选中字段摘要；不调用 `toString`/getter（避免副作用和懒加载）；循环引用检测。
- JPA 懒加载代理：直接读字段不安全时输出 `LazyProxy` 占位，不触发数据库查询。
- 集合：记录大小、首尾/样本；不默认全量。
- 循环：合并 + 样本 + 计数；避免 10 万次写入把会话撑爆。
- 敏感字段：默认按字段名/注解/正则脱敏（password、token、secret、authorization、cookie、idcard、phone、email、bankcard 等）；HTTP 头白名单；请求/响应体、SQL 参数都过脱敏。
- 本地允许用户显式关闭脱敏用于自己的调试；云端强制脱敏，不提供关闭开关。
- 脱敏后显示长度/哈希/占位符，而不是空字符串；让用户知道“这里有值但被保护”。

**100→0→100 的行级示例：** `amount` 入参 100 → 第 42 行赋值 0 → 第 47 行又改回 100。详情按行列出三条 old→new；即使最终返回值看起来正常，也能看到中间第 42 行是第一个分歧点。循环里的重复写入折叠为“第 1..N 次”，保留样本，不把 10 万次写入全部塞进会话。

### 9.4 开销目标与测量

| 档位 | 目标（示例项目，p95 额外延迟） | 失败时 |
|---|---|---|
| L0 | ≤ 8% | 降低采样/缩窄包范围 |
| L1 | ≤ 25% | 自动降级字段/集合预算 |
| L2 | ≤ 40%（仅选中方法/单请求） | 只保留局部变量/字段写入，关闭其余 |
| 前端构建 | 构建时间增加 ≤ 25% | 对该项目降级为 runtime-only，并提示 |

- 测量方法：JMH 微基准 + 200 次脚本化点击回归 + agent 自报 self-time + 对比无 agent 的基线；工作台展示“本次采集开销”。
- 目标是验收门槛，不是对所有应用的无条件承诺；不达标就降级并公开说明。

## 10. 云端模式

### 10.1 适用与不适用

**适用：** 非敏感的测试项目、示例项目、教学/比赛演示、需要快速看效果且不想装本地环境的人。

**不适用：** 真实客户数据、内网依赖（Redis/MQ/SSO/第三方回调）、需要外部测试数据库、需要用户本机登录态、长驻服务、生产流量、GPU/大内存、GraalVM native。

如果用户的项目含真实业务数据，默认推荐本地模式。

### 10.2 上传清单、保留与清理

| 文件 | 必需 | 用途 | 默认保留 |
|---|---|---|---|
| 可执行 JAR | 与 WAR 二选一 | Spring Boot 运行 | 随工作区；工作区空闲 24h 后删除，最长 7 天 |
| WAR | 首发否（本地可用） | 云端 P4 才接收；首发只收 Boot JAR | 同上 |
| 前端 dist.zip | 否（前端已打进 JAR/WAR 时不需要） | 独立前端 | 同上 |
| sourcemap | 否 | 前端原始名字/行号 | 随工作区/会话，默认 7 天 |
| 前端 trace build 产物 | 否 | JS 深层变量 | 同上 |
| 源码 zip | 否 | 仅展示源码片段 | 加密存储，随工作区删除 |
| schema/seed SQL | 否 | 测试数据库初始化 | 随工作区删除 |
| 环境变量/启动参数 | 否 | 启动配置 | 加密；日志中不显示 secret；随工作区删除 |
| 调试记录/日志 | 自动 | 回放与诊断 | 云端默认 7 天，可手动删除/导出 |

- **首发云端只接收可执行 JAR**；WAR 在本地模式完整支持，云端 WAR 作为 P4 增强，不阻塞首发。
- 上传前检查：大小、类型、hash、zip slip/zip bomb、JAR manifest/main class、WAR 结构、class major version、前端 index。
- **制品内可能自带配置/密钥**：平台不能替你清理 JAR/WAR 里的 secret；含真实数据或密钥的包不要上传云端，改用本地模式。
- **sourcemap 可能包含 `sourcesContent`（源码）**：上传 sourcemap 等同于上传源码片段，按源码同等级加密/保留/删除；用户需知情。
- 默认配额：单 JAR ≤ 200MB、WAR ≤ 300MB、dist ≤ 100MB；每用户 5 个工作区/2GB；单次运行 30–60 分钟。
- 清理：工作区空闲 24h 或达到 7 天上限自动删除；用户可立即删除；调度器定期清理临时文件、容器、数据库、预览 token；删除后不可恢复（备份轮转 24h 内清除）。
- 不上传：本地源码（除非明确上传）、真实数据库全量 dump、无关浏览器数据、用户机器上的其他文件。

### 10.3 启动失败怎么让用户知道

分阶段诊断卡：

1. **上传校验**：文件损坏、非可执行 JAR、无 main、WAR 结构不对、前端 index 缺失、类版本不支持。
2. **JVM 启动**：Java 版本不匹配（`UnsupportedClassVersionError`）、内存不足、缺 native 库、启动即退出；显示 exit code 和 stderr 尾部。
3. **框架启动**：Spring context 失败、bean 冲突、缺配置、profile 不对；从日志提取关键异常。
4. **数据库**：连接拒绝/认证失败/驱动缺失/Flyway 校验失败/schema 不存在/seed 失败；给出可操作建议。
5. **端口/健康**：端口占用、健康检查 5xx、根路径 404、静态资源 404、context path 不匹配。
6. **前端预览**：index 404、base path 错误、CSP 拦截注入、API 绝对地址指向 localhost、资源 404；给出修复选项。
7. **网络策略**：应用尝试外网被阻断；提示“云端默认禁止出网；如需外部服务请用本地模式”。

诊断不是猜谜：每张卡包含“检测到什么、最可能的原因、下一步动作、相关日志行”。用户可以改环境变量/启动参数后重试，不能获得 shell。

### 10.4 测试数据库怎么办

- 应用自带 H2：直接用；重启时按配置重置。
- MySQL/PostgreSQL：平台为每个工作区提供隔离数据库/schema + 受限账号；用户上传 `schema.sql`/`seed.sql`（或由应用迁移脚本创建）；平台注入连接配置；可一键重置数据。
- 外部测试数据库：**云端默认不允许**（出网 deny，避免把真实数据/内网暴露给不可信应用）。需要外部库的用户使用本地模式。
- 数据库账号只对自己的 schema 有权限；不能用 root；数据库网络只对工作区可见；不暴露管理控制台。
- 不默认镜像整表数据；调试看 SQL/行数/实体字段，不承诺查看数据库任意历史版本。

### 10.5 隔离与安全（不可打折）

- 不可信 JAR/WAR 是“任意代码”；普通容器不是强安全边界。**公开上传必须使用强隔离（Firecracker 等 VM 级沙箱，或经过安全评估的 gVisor 级沙箱）**；未达到该门槛前，云端只做受邀演示/预置项目，不开放任意上传。
- 每个会话：独立 microVM/沙箱、非 root、只读 rootfs、tmpfs 配额、CPU/内存/pids 限制、无外网（默认 deny）、运行超时、不可挂载宿主目录、不可访问 Docker socket。
- 数据库、对象存储、预览、日志按工作区隔离；对象存储前缀 + 短时签名 URL；跨租户访问测试必须全部失败。
- 预览页面与工作台**不同源**：不可信应用拿不到工作台 cookie/localStorage；预览使用短时、会话级 token。
- 上传文件只对所有者可见；日志/事件默认加密存储；删除即从可访问存储移除。
- 前端 SDK 注入需要处理 CSP；注入失败时明确提示，不用“图很完整”掩盖前端未接入。
- 云端强制脱敏；用户不能关闭。
- 云端安全门槛：跨租户越权、出网、zip slip、路径穿越、命令注入、预览 token 重放，全部有自动化测试；未通过不公开。

### 10.6 镜像与兼容矩阵

计划验证组合（发布前逐项有 CI 报告；未通过就不标“支持”）：

- Spring Boot 2.7 + JDK 8/11 + JAR
- Spring Boot 3.x + JDK 17/21 + JAR
- Tomcat 8.5 + JDK 8 + WAR（EOL，只读支持）
- Tomcat 9 + JDK 11 + WAR
- Tomcat 10.1 + JDK 17 + WAR（jakarta）
- 前端：Vue3/Vite、React18/Webpack5（trace build）

- 首发云端只验证 Boot JAR + Vue/React；Tomcat 组合用于本地模式与 P4 云端 WAR，不属于 P3 首发门槛。

每个组合都要有示例应用和 CI 冒烟；矩阵单元通过才有“支持”标签。

### 10.7 云端能覆盖三类环境的什么程度

- **Spring Boot JAR + Vue3/React**：P3 目标完整（图/详情/回放/请求切换/L2 视阶段）。
- **Tomcat WAR + SSM + Vue3/React**：P2 本地完整；云端首发不接收 WAR；P4 开放云端 WAR（按矩阵分基础/完整），不作为首发门槛。
- **JSP/Thymeleaf 服务端渲染**：页面级（F0）支持；JS 深层/组件映射不承诺。
- **WebFlux、微服务全链路、多 JVM**：V1 不支持完整图；traceparent 预留，显示为边界/未采集。

## 11. 本地模式

### 11.1 形态

- 本地启动器 + 本地工作台 + agent + 前端 SDK/构建插件；全部打包，资源本地加载，不依赖 CDN。
- 数据存储在工作区目录（建议 `%USERPROFILE%\.traceboard`，ASCII 路径）：SQLite/事件文件；可配置加密；可导出/删除。
- 只监听 `127.0.0.1`；每次启动生成 token；agent 用 token 握手。
- 工作台需要 Java 21（最终安装包内置精简 JRE）；被调试项目可以是 JDK 8/11/17/21。
- 无遥测、无默认外网请求；断网可用（许可证用本地文件/无需联网）。

### 11.2 “我平常就在 IDEA 里启动项目”（Spring Boot）

1. 安装/打开本地启动器，新建工作区，选择 IDEA Spring Boot。
2. 启动器显示一段带引号的 VM options：
   ```text
   -javaagent:"C:\Users\13357\.traceboard\traceboard-agent.jar"=workspace=<id>,token=<token>,ingest=http://127.0.0.1:<port>,profile=L1
   ```
3. 在 IDEA 的 Run/Debug Configurations → 对应 Spring Boot 配置 → VM options 粘贴；启动应用。
4. 启动器检测 agent 握手；打开工作台；使用预览代理地址访问应用（同源注入前端 SDK）。
5. 如果应用已在运行：可以尝试动态 attach，但界面明确“之前的操作未采集”；JDK 21 可能提示动态加载限制，推荐重启并加启动参数。

**诊断重点：** 项目 JDK 与 agent/工作台版本、路径含空格/中文的引号、agent 未加载、端口占用、Token 不匹配、已有 JaCoCo/APM agent 冲突。

### 11.3 “我在 IDEA 里启动 Tomcat”

1. 选择 IDEA Tomcat 接入。
2. agent 参数加到 Tomcat Server 的 VM options（或 `setenv.bat`/`CATALINA_OPTS`），不是在 webapp 代码里。
3. 启动 Tomcat；启动器连接；预览代理打开应用。
4. IDEA 管理 Tomcat 生命周期时，启动器不接管；只做采集、预览和诊断。
5. 如果 IDEA 临时 `CATALINA_BASE`/context path 导致 404，诊断卡显示实际 context path、端口和 URL。

### 11.4 “我手里只有打好的包”（JAR）

1. 选择只有 JAR；选择本机 JDK（8/11/17/21）、启动参数、环境变量、端口。
2. 启动器生成并执行：
   ```text
   "<jdk>\bin\java.exe" -javaagent:"...traceboard-agent.jar"=<...> -jar app.jar
   ```
3. 解析 stdout/stderr；应用健康检查；打开预览。
4. 支持停止/重启/重置；启动失败显示 Spring Boot FailureAnalyzer 常见原因。
5. 不要求源码；没有源码仍可看方法/行号（若字节码有调试信息）与运行时值。

### 11.5 “我只有 WAR”（本机 Tomcat）

1. 选择 WAR；启动器让你选择 Tomcat 安装目录（自动检测/记住）。
2. 启动器在工作区创建独立 `CATALINA_BASE`，复用 `CATALINA_HOME`，把 WAR 放进 webapps，选择空闲端口，生成 `setenv` 加 agent，启动。
3. 不修改用户原有 Tomcat 配置；停止后清理临时 base（可保留日志）。
4. 诊断：`CATALINA_HOME` 不存在/指向错误（本机已中招）、Tomcat 与 jakarta/javax 不匹配、WAR 解压失败、context path、JDK 版本、端口冲突。

**本机真实问题（必须做成演示/测试）：** `CATALINA_HOME=E:\apache-tomcat-8.5.60` 不存在，实际 Tomcat 在 `D:\apache-tomcat-8.5.60\apache-tomcat-8.5.60`。本地启动器应自动发现并提示，而不是让用户看空日志。

### 11.6 前端单独用 Vite/Webpack 开发服务器

- 在 Vite/Webpack 配置中加 TraceBoard 插件；产出 manifest/sourcemap；插件能拿到控件→处理器、局部变量、回调。
- 后端仍按上面接 agent；工作台可以代理前端 dev server 与后端，或让用户直接用原 dev URL（需要 CORS/header 配置）。
- 如果无法改构建：使用 runtime SDK（页面注入/手动 script），只到 F0/F1，明确提示“没有 JS 内部变量”。
- 同源代理优先，避免 trace header 触发 CORS preflight；跨域时必须允许 trace header，否则降级 `INFERRED/LOST`。

### 11.7 代理、注入与 CSP

- 本地默认通过工作台反代 `/app/` 访问应用：同源、可注入 SDK、可处理相对路径。
- 对 HTML 响应注入脚本；处理 gzip/br；如果应用有严格 CSP，注入可能失败：
  - 尝试带 nonce/hash 的注入；
  - 失败则提示“前端采集未接入”，建议用构建插件打包 SDK 或手动加 script；
  - 不修改业务 JS 逻辑。
- 应用 API 使用绝对地址（如 `http://localhost:8080`）时，代理可能需要重写或用户配置 base URL；诊断卡明确原因。

### 11.8 本地诊断清单

- agent 未加载：VM options 位置不对、引号/路径空格/中文、agent 文件不存在、启动命令顺序。
- agent 已加载但工作台未连接：token、ingest 地址、端口、多个应用实例。
- 前端未接入：CSP、注入被过滤、代理未生效、不是 HTML 响应。
- 页面 404：context path、代理 path、SPA fallback。
- 数据库：MySQL 驱动、时区、账号、schema、端口。
- 版本：工作台 JDK、目标 JDK、Tomcat/Jakarta、类版本。
- 采集缺口：调试信息缺失、L2 未开、第三方包被排除、录制暂停。
- 已有 agent 冲突：JaCoCo、APM、热部署；提示调整顺序或换端口。

### 11.9 隐私与离线

- 程序、调试记录、工作台默认全部留在本机；不上传代码/变量/SQL/日志。
- 默认脱敏；本地可显式关闭（用户自己的数据）；导出前可再次脱敏。
- 本地数据可加密；可一键清除；可设置保留期限；不发送遥测。
- 断网测试作为发布门槛：禁用网络后仍能启动、接入、看图、回放；不依赖字体/CDN/许可证服务器。
- 只有一种情况会出网：用户主动点击外链/手动下载；产品本身不自动访问公网。

### 11.10 本地四种接入的验收

| 接入 | 验收 |
|---|---|
| IDEA Spring Boot | 新手按文档 ≤10 分钟完成；agent 握手；首次点击出图；无源码也能看后端事实 |
| IDEA Tomcat | 正确加 agent；context path/端口正确；WAR 部署；图不混入 IDEA 自身请求 |
| JAR | 启动器选择 JDK/参数；失败诊断可操作；首次点击出图 |
| WAR | 自动检测 Tomcat 路径；独立 CATALINA_BASE；不污染原 Tomcat；停止/清理正确；重部署 20 次无 ClassLoader 泄漏/OOM |

## 12. 两种模式共用一套

### 12.1 共用契约

- 同一个事件 schema（`traceboard.event.v1`）：session/span/value/sideEffect/correlation/status/flags。
- 同一个图构建器（增量 append+patch）、同一个节点详情组件、同一个时间轴/回放逻辑。
- 同一套教程/keyboard shortcuts/图例；云端学会，本地照用。
- 同一个前端 runtime SDK/构建插件；本地代理与云端预览只是注入通道不同。
- 同一个 agent（JDK 8 目标）；云端与本地的差异只在启动/传输/存储/鉴权。

### 12.2 差异

| 方面 | 本地 | 云端 |
|---|---|---|
| 运行位置 | 用户机器 | 隔离沙箱 |
| 数据 | 本机文件、可加密 | 云端对象存储/数据库，按工作区隔离 |
| 接入 | IDEA/JAR/WAR 向导 | 上传/选择版本/环境变量 |
| 前端注入 | 本地反代 | 云端预览反代 + 短时 token |
| 保留 | 用户决定 | 24h 空闲/7 天上限，可删 |
| 网络 | 可用用户本机依赖 | 默认无出网 |
| 隐私 | 数据不出机 | 强制脱敏、加密、访问控制 |

### 12.3 一致性测试

用同一个示例会话分别在本地/云端录制：比较节点 key/边/调用次数/状态/关键值/回放时间点快照；差异只允许出现在环境元数据（路径、主机、时间），不允许图语义不同。作为 P3 验收门槛。

## 13. 架构与技术选型

### 13.1 组件

```text
┌──────────────┐   事件流    ┌─────────────────┐   查询/推送   ┌──────────────┐
│ Front SDK /  │ ─────────▶ │ Collector        │ ───────────▶ │ Workbench    │
│ Build Plugin │            │ Ingest/Normalize │              │ Vue3         │
└──────────────┘            │ Correlation      │              │ Graph/Detail │
┌──────────────┐            │ Graph patch      │              │ Timeline     │
│ Java Agent   │ ─────────▶ │ Storage          │ ◀─────────── │ Replay(只读) │
└──────────────┘            └─────────────────┘              └──────────────┘
       ▲                              ▲
       │ 启动/attach                   │ 本地进程 / 云端沙箱
┌──────┴───────┐              ┌───────┴────────┐
│ Local Launcher│              │ Cloud Orchestr. │
│ IDEA/JAR/WAR  │              │ microVM/镜像/DB │
└───────────────┘              └────────────────┘
```

- **唯一事实源**：append-only 事件流；图、详情、回放都是派生。
- **GraphBuilder 流式**：append+patch，支持首次失败即出图、断链仍可渲染；不等待全量批处理。
- **Correlation Engine**：规则状态机，前后端共用同一规则表；产出置信度与游离片段。
- **Launcher 抽象**：`LaunchSpec → RunningApp{url, ingestUrl, logs, exitCode}`；本地 spawn 进程，云端起沙箱；不参与图逻辑。

### 13.2 平台技术栈

- 平台服务/启动器/云端编排：Java 21 + Spring Boot 3.x + Maven 多模块。
- agent：Java 8 字节码目标；Byte Buddy（入口/主机适配）+ ASM（字段/行级探针）组合，具体版本以满足 JDK 8–21 的实测为准。
- 工作台：Vue3 + TypeScript + Vite + Pinia；图渲染用 Cytoscape.js + ELK/Dagre 分层布局；时间轴自研；桌面优先。
- 前端插件：共享 Babel AST 插桩核心，Vite 插件/Webpack loader 薄适配；Vue/React 各自组件/事件适配器。
- 存储：本地 SQLite + 事件文件；云端 PostgreSQL + 对象存储（S3 兼容）；内容寻址值去重。
- 传输：Ingest 批量 HTTP + 实时 WebSocket/SSE；回放只读 HTTP。
- 沙箱：公开云端用 microVM/gVisor 级；未达标前受邀演示。
- 构建环境：本机 Node 22.22.2/npm 10.9.7；Maven 3.9.5；平台构建 JDK 21；agent 用 `--release 8`。

### 13.5 安全边界

- agent 不做远程代码执行；配置/握手用本地 token 或云端工作区 token；只连接指定 ingest。
- 不可信应用：沙箱；无外网；预览与工作台不同源；token 短时；对象存储隔离。
- agent 失败不能破坏应用：fail-open + 可见缺口，而不是让应用起不来。
- 日志/事件默认脱敏；本地可关闭脱敏但必须显式确认；云端强制。
- 源码可选、加密、随工作区删除；不用于训练；无隐藏遥测。

## 14. 支持矩阵：完整 / 基础 / 仅本地 / 暂不支持

### 14.1 定义

- **完整**：方法级前后端图 + 请求切换 + 关键读数/SQL/UI 效果 + 回放 + 明确缺口；有示例/CI。
- **基础**：能看控件/请求/后端方法或行数，但某些深层变量/组件映射/异步回调不完整。
- **仅本地**：只在本地模式支持；云端因隔离/依赖/成本不支持或未验证。
- **暂不支持**：V1 不承诺；界面应直接说明，而不是空图。

### 14.2 矩阵（目标，按阶段交付）

| 被调试环境 | 本地 | 云端 | 说明 |
|---|---|---|---|
| Spring Boot 2.7 + JDK 8/11 + JAR + MyBatis/JPA | 完整（P1） | 完整（P3） | 主路径；0 行/SQL/字段 diff |
| Spring Boot 3.x + JDK 17/21 + JAR | 完整（P1） | 完整（P3） | jakarta 适配 |
| Vue3 + Vite + Axios | 完整（P1/P2） | 完整（P3） | F2 构建插件深层 |
| React18 + Webpack5 | 完整（P2） | 完整（P3） | 共享 Babel 核心 + React 适配 |
| Tomcat 8.5/9 + WAR + SSM + javax + Vue/React | 完整（P2） | 后续（P4） | 首发云端不接收；8.5 EOL |
| Tomcat 10.1 + WAR + jakarta | 完整（P2/P4） | 后续（P4） | jakarta 适配；首发云端不接收 |
| JSP/Thymeleaf 服务端渲染 | 基础（页面级） | 暂不支持（首发）/P4 视 WAR | 无 JS 深层；服务端模板不展开 |
| 纯 Servlet/JSP | 基础 | 暂不支持 | 请求/方法基础；无 SPA 深度 |
| WebFlux/Reactor | 暂不支持 | 暂不支持 | 响应式链路 V1 不做 |
| Kotlin 协程 | 基础/实验 | 暂不支持 | 方法可插桩，协程上下文不承诺 |
| GraalVM native / 字节码加密 / 强混淆 | 暂不支持/仅基础 | 暂不支持 | 无运行时字节码插桩或名字不可用 |
| 多微服务/网关全链路 | 暂不支持 | 暂不支持 | 单 JVM；traceparent 预留 |
| 无构建插件/无 sourcemap 前端 | 基础（F0/F1） | 基础 | 无 JS 局部变量/原始行号 |
| 无调试信息 JAR | 基础 | 基础 | 无局部变量名/行号；方法/SQL 事实仍有 |
| JDK 22+ | 暂不支持 | 暂不支持 | 未验证；给出错误/建议本地降级 |
| 动态 attach 已运行项目 | 基础 | 不适用 | 漏早期事件；JDK21 限制 |

**拒绝“支持 Boot”这种粒度**：每个单元必须写到“Boot 版本 + JDK + 宿主(JAR/WAR) + 前端构建 + 深度级别”，并通过对应 CI 用例。

### 14.3 兼容性证据

- CI 矩阵：JDK 8/11/17/21 × 示例应用；每个单元至少一条端到端点击用例。
- 字节码主版本检测 + 上传/启动前错误信息。
- agent JDK 8 目标，平台 JDK 21；两端分开构建。
- 通过报告随版本发布；没有报告的单元默认“暂不支持”，不靠口头承诺。

## 15. 分阶段开发与验收（历史三人周期；单人见 SOLO-PLAN）

> **本节周期是三人模式的历史估算，不是单人排期。** 当前单人开发以 [SOLO-PLAN.md](SOLO-PLAN.md) 的 S0–S10 检查点和范围为准；本节的验收内容可作为参考，但不要按“3 人/多少周”安排当前任务。
>
> 单人模式不使用 A/B/C 三线并行、三人会签或按天/周同步；完成检查点就停止、自检、提交。

### P0 技术验证（2–3 周）

**目标：** 证明“首次失败出图 + 0 行事实 + 纯前端无请求 + 回放不重放”是真实可做，不是 UI 假象。

**范围：**
- `BuggyShop` Boot2.7/JDK8 + Vue3/Vite + MyBatis + MySQL/H2。
- agent：L0 + 窄范围 L1 实体字段 diff；Controller/Service/Mapper/SQL 行数/异常/入参返回。
- 前端：runtime SDK（点击/请求/DOM）+ 最小 Vite 插件（案例 B 的校验变量）。
- traceparent/clickId 关联；后台轮询分离；最小图页面（不追求完整 UI）。
- 事件流/回放的最小验证；自动断言回放无写。

**验收门：**
- 3 个含缺陷样例，均从未成功运行的状态直接出图。
- 案例 A 3 次点击内看到 SQL 0 行/Mapper 0/Service true/无异常。
- 案例 B 证明请求数 0（或“无法确认”区分正确）。
- 20 次含轮询点击，误并入 0 次。
- 回放期间写 SQL/写 HTTP = 0（自动断言）。
- 示例项目已执行方法覆盖率 ≥95%（排除框架）；图增量更新 ≤1s。
- L0 p95 额外延迟 ≤8%；若 L2 局部变量不可行，记录并推迟，不阻塞 P0。
- **Go/No-Go：** 若 Java 事实链或关联不可靠，停下重设方案，不用漂亮 UI 掩盖。

### P1 本地 MVP（5–7 周）

**目标：** 用户能在自己的 Spring Boot + Vue 项目里完成一次真实定位。

**范围：**
- 本地启动器（IDEA Boot + JAR）、SQLite 会话、预览反代/注入。
- 工作台：左右分图、请求切换、节点详情、时间轴、回放、状态语义、采集范围/缺口。
- 前端 F1 sourcemap + Vite/Vue F2 基础；后端 L0/L1；实体字段 diff；×N 调用；脱敏/截断/丢弃标记。
- 诊断、导出会话、离线检查、基础教程/坏示例。

**验收门：**
- 新手按文档接入 ≤10 分钟（IDEA）/≤5 分钟（JAR），至少 3 人测试。
- 案例 A/B 在正式 UI 中完成；用户 ≤5 分钟指出目标方法。
- 多请求/刷新/后台轮询归属正确；切换正确。
- ×3 方法可逐次查看；L1 字段 diff 至少一个 100→0 场景可见。
- 所有缺口有原因；无静默丢弃。
- L1 p95 ≤25%；回放 0 写；断网本地可用（无 CDN/遥测）。
- 后端 JDK8/21 本地实测；11/17 由 CI/补装验证（不冒充本机已验证）。

### P2 本地全栈覆盖 + 深度（5–7 周）

**目标：** 覆盖三类被调试环境；把“行级变量/实体字段/重复调用/异步回调”做实。

**范围：**
- React18/Webpack5；共享 Babel 插桩；Vue/React 组件/事件适配；sourcemap/manifest。
- Tomcat 8.5/9/10.1 WAR + SSM；javax/jakarta；IDEA Tomcat + WAR-only 两种接入；独立 CATALINA_BASE。
- L2 选中方法行级局部变量/字段写入；循环折叠；懒加载代理占位；L2 预算。
- 异步线程池/CompletableFuture/@Async 上下文；前端 Promise/async 回调上下文（尽力，缺标 LOST）。
- 接口→实现展示；实体创建/修改；UI 效果摘要；手工关联；游离片段。
- 四种本地接入验收；重部署泄漏测试。

**验收门：**
- 三个示例应用（Boot+Vue、Boot+React、Tomcat WAR+Vue/React）均跑通案例 A/B。
- L2 能在选中方法指出 100→0 的行/字段；缺调试信息时明确 `NO_DEBUG_INFO`，不猜。
- 同一方法 ×3，错误发生在第 2 次时能定位。
- Tomcat 重部署 20 次无 ClassLoader 泄漏/OOM；CATALINA_HOME 无效可诊断。
- 前端构建时间增加 ≤25%；L1 ≤25%、L2 ≤40%（选中方法）。
- 异步关联正确率目标 ≥90%；丢失必须标 LOST，不能误连。

### P3 云端模式（4–6 周）

**目标：** 上传即运行、在线预览、同一套图；安全隔离达标。首发只接收 Boot JAR。

**范围：**
- 账号/工作区/上传/配额；沙箱（公开需 microVM/强沙箱）；JDK 8/11/17/21 镜像（Boot 组合）；隔离数据库/schema + seed；启动诊断；预览注入/短时 token。
- Boot JAR + Vue/React 完整；**首发不做云端 WAR**，WAR 本地完整、云端 P4 再开。
- 保留/清理/删除/导出；跨租户安全测试；云本地一致性测试。
- 云端工作台复用 P1/P2 组件。

**验收门：**
- 上传到可预览 ≤90s（小示例，冷启动目标）；失败有分阶段诊断。
- 类版本/DB 认证/端口/Flyway/404 等启动错误 ≤3 分钟给出可操作建议。
- 跨租户访问、出网、预览 token 重放全部阻断；预览与工作台不同源。
- 文件保留/删除/清理按声明执行；无残留容器/数据库/对象。
- 案例 A/B、回放、请求切换与本地一致；一致性快照通过。
- 首发验收只覆盖 Boot JAR；WAR 不在本阶段范围。
- 公开上传安全门槛未达则只开受邀演示，不硬上。

### P4 深度与硬化（5–7 周）

**目标：** 能对外首发/比赛演示的完成度；补齐兼容与体验。

**范围：**
- 云端 WAR（V1.x 增强，不作为首发门槛）、更多 Tomcat/React 版本、虚拟线程实验标记。
- UI 效果更细（toast 文本/表格行摘要/按钮状态/路由）；不引入像素级 DOM 回放（已确认事件级语义）。
- 安装包（内置 JRE）、IDE 插件/一键配置（可选）、导出/导入、会话对比。
- 性能、可访问性、国际化、文档/教程、用户测试、安全审查。
- 支持矩阵 CI 全覆盖；发布报告。

**验收门：**
- 支持矩阵每个“完整/基础”单元有 CI 用例和报告。
- 本地安装包断网可用；无遥测；数据删除/加密验证。
- 3–5 名新手测试：接入 ≤10 分钟，案例 A 定位 ≤5 分钟；不误导。
- L0/L1/L2 开销报告公开；超预算自动降级且可见。
- 回放 0 执行断言持续通过。

### 15.1 最小可演示路径（比赛/评审）

- P0 + P1：本地 Boot+Vue，3 分钟演示：
  1. 打开坏示例，点击保存；
  2. 实时亮图，右图 SQL 0 行、Service 返回 true；
  3. 点 Mapper/Service 读事实，给出结论；
  4. 切刷新请求、展示后台轮询不并入；
  5. 切纯前端案例，证明请求没发；
  6. 拖时间轴回放，强调“只读、不再下单”；
  7. 展示一个“未采集”标记，说明不假装完整；
  8. 本地模式断网/数据不出机一句话。
- 云端作为“路线图/受邀演示”，不在隔离未达标时开放任意上传。

### 15.2 排期风险

- P0/P1 是核心，不要被 UI 美化拖慢。
- P2 的 React 事件映射、Tomcat ClassLoader、L2 字节码是三大风险，预留缓冲。
- P3 的沙箱/镜像/DB 是安全敏感项，宁可晚，不可假。
- P4 容易范围膨胀；以支持矩阵和用户测试收口。

## 17. 风险、降级与不承诺

### 17.1 主要风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 范围过大（三类环境 + 云端 + 深度） | 每项都浅 | 先 P0/P1 垂直闭环；P2 扩栈；矩阵分深度；不为“全覆盖”牺牲事实链 |
| 局部变量采集脆弱 | L2 不可靠/VerifyError | 仅选中方法；检查 LocalVariableTable；失败跳过并标原因；不猜 |
| 前端无构建插件/无 sourcemap | JS 内部黑盒 | F0/F1 仍提供控件/请求/DOM 证据；明确缺口；引导升级 |
| 异步/跨线程/网关丢上下文 | 关联错误 | traceparent + 置信度；LOST/游离区；手工关联；不硬连 |
| CORS/header 被剥 | 前后端连不上 | 本地/云端同源代理；agent 允许 header；指纹降级；标 INFERRED |
| Java 版本/框架组合爆炸 | “支持”名不副实 | 6 单元矩阵 + CI；每单元示例；无报告=不支持 |
| Tomcat ClassLoader/热部署泄漏 | 内存问题 | per-ClassLoader WeakHashMap；重部署测试；fail-open |
| 采集开销 | 应用变慢 | L0/L1/L2 预算；采样/折叠；自动降级；公开测量 |
| 云端不可信代码 | 安全/越权 | microVM/gVisor；无出网；非 root；隔离 DB/对象；公开门槛 |
| 隐私 | 用户不敢用 | 本地优先；默认脱敏；加密；保留/删除；强制云端脱敏 |
| 回放被误解为“重跑” | 重复下单风险 | 只读事件流；无重跑按钮；自动断言 0 写；界面常驻提示 |
| 比赛排期 | 做不完 | P0+P1 最小演示；云端/矩阵按时间裁剪；不造假 |

### 17.2 降级原则

1. 先保住事实：方法是否执行、返回/异常、SQL 行数、请求是否发出。
2. 再保关联：关联不上就 LOST/游离，不强行连。
3. 再保细节：变量/字段可 L1/L2 分级；缺就标原因。
4. 最后保覆盖：不支持的环境直接说明，不生成空图冒充成功。

### 17.3 明确不承诺

- 不承诺记录所有变量、所有对象、所有第三方内部调用；不承诺“完整调用图”。
- 不承诺像素级页面回放/DOM 快照（V1 只做图+记录摘要）。
- 不承诺没有调试信息/混淆时还原原始变量名/源码。
- 不承诺所有异步/跨线程/跨服务自动关联；有置信度和手工关联。
- 不承诺 WebFlux、GraalVM native、Kotlin 协程、JDK 22+、微服务全链路。
- 不承诺云端可访问内网/外部真实数据库/第三方回调/生产流量。
- 不承诺自动判断业务对错或自动修复；只给事实与定位。

### 20.4 Qoder 使用规则（三人一致）

- **共享上下文：** 仓库根放 `AGENTS.md`（或 `qoder.md`）写清架构、模块 ownership、契约路径、构建/测试命令、禁止事项；每个人开 Qoder 会话先读它。
- **一个模块一个 owner agent：** A 的会话只改 `agent/` 和 demo 后端；B 只改 `server/`/schema；C 只改 `workbench/`/`frontend/`。需要跨模块时先提契约变更，不在别人文件里“顺手改”。
- **任务提示模板：** 目标、相关契约、验收命令、禁止修改的目录、需要产出的测试。让 Qoder 先读契约和 fixture，再写代码；高风险改动先 plan；写完运行 `scripts/verify`；再用一个 review agent 自查。
- **分支/worktree：** 先 `git init` + `.gitignore`；`main` 保持可运行；每人用短分支或独立 worktree（`feat/agent-*`、`feat/platform-*`、`feat/web-*`）；小 PR，检查点/接口确认后集成；不直接 push main。
- **契约测试/生成代码：** schema/API 类型由脚本生成；生成文件不手改；字段变更加兼容测试。UI 先用 fixture，后端先用 mock，避免互相等待。
- **禁止事项：** 不让两个 Qoder agent 同时改同一文件；不把真实 secret/客户数据贴进 prompt；不自动下载 GitHub/无国内镜像资源（按本项目偏好给用户链接）；不把未验证的 AI 输出直接合并。
- **Stop-and-Sync 硬规则：** 到达个人计划的 `SYNC` 检查点，停止继续修改，输出进度包和 `SYNC REQUIRED`，等待明确“继续”；不得自动跨过。同步不按天/周，只看检查点完成、契约/语义/隐私变更、跨边界故障、阶段门或发布。
- **同步范围：** `LOCAL` 只更新自己的计划；`INTERFACE` 与受影响者对齐；`ALL` 三人共同确认。阶段门只有在 A/B/C 对应检查点都完成且集成证据通过时才通过。

### 20.8 Definition of Done（每个人提交前）

- 有对应契约/验收用例；至少一个正常 + 一个“未采集/错误”路径。

- 无 secret/真实数据进入日志、fixture、prompt；默认脱敏。
- 性能预算：L0/L1 档不超第 9 节目标；前端构建增量可测。
- 有 review（Qoder review agent + 人类 owner）；文档/README 更新；可回滚。

### 20.9 三人排期与裁剪

## 附录 A：术语（给 Java 新手）

- **JVM**：运行 Java 程序的虚拟机。
- **agent**：通过启动参数加载进 JVM 的小程序，能在类加载时插入探针，不需要改业务代码。
- **字节码/插桩**：Java 编译后的中间代码；插桩是在方法进出等位置加入很小的记录代码。
- **断点/单步**：让程序停下来、一步一步执行的调试方式；本产品不提供。
- **sourcemap**：把压缩后的 JS 位置映射回源码文件/行号；不包含变量值。
- **trace/span**：一次操作/一次调用的记录；trace 是整条链，span 是其中一段。
- **CATALINA_HOME / CATALINA_BASE**：Tomcat 安装目录 / 某个运行实例的配置与工作目录。
- **WAR/JAR**：Java Web 应用包 / Java 可执行包；Spring Boot 常用可执行 JAR。
- **L0/L1/L2**：采集档位；L0 基础事实，L1 对象/字段摘要，L2 选中方法的行级变量。
- **脱敏/截断/采样**：值被隐藏/截短/只记录一部分；界面必须标记，不能静默。

## 附录 C：事实最小集与事件示例

一次操作至少要能回答：

1. 用户点了哪个控件？（ID/名称/DOM 路径/位置）
2. 触发了哪个前端处理器/校验/请求？（无插件时标明未采集）
3. 发了哪些请求？哪些属于本次操作？哪些是后台？
4. 请求到了哪个 Controller？实际执行哪个实现类？
5. 方法返回/异常是什么？耗时多少？调用了几次？
6. SQL 影响多少行？事务成功还是回滚？
7. 实体/变量在哪里从什么变成什么？（按采集档位）
8. 响应后页面发生了什么？提示/表格/按钮/路由？
9. 哪些环节没有采集到，为什么，怎么开启？

事件示例见 13.4；完整 JSON Schema 在开发时落到 `schema/traceboard.event.v1.json`，由 Java/TypeScript 共享生成，避免两端字段漂移。

## 结语

这个产品的核心竞争力不是“画得像个电路板”，而是：

> **在一次真实失败的操作里，把跨前端、跨 HTTP、跨 JVM 方法、跨 SQL 的事实连起来，并且诚实标出断点在哪里。**

先把 P0 的事实链跑通，再谈云端和覆盖矩阵；任何“看起来完整”的图，只要有一处静默缺失，就会破坏用户对它的信任。
